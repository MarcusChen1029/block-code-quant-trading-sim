# Signals (step 1 of 2) — design note (2026-10-07)

Pine calls that mark events become SIGNAL outputs: true/false per bar, a Boolean `sig_<id>` block, and chart
markers. Step 2 (native order-block / FVG zones) is not built; zones will be a separate optional list on
`IndicatorBlockDef` next to `outputs` and `signals`, with their own overlay drawing, so nothing here changes.

## Pine (src/pine/signals.ts, analyze.ts, codegen.ts)
- `plotshape`, `plotchar`, `alertcondition` and `label.new(bar_index | time, y, "Text", ...)` are signals in
  v4/v5/v6. They are statements (anywhere except inside user functions; inside `if` / `for` they fire only when
  that line runs). Slots reset to 0 every bar, so unexecuted and `na` / `false` / `0` mean false.
- Names: `title` literal, else `text` literal (alertcondition: `message`), else `Signal N` / `Alert N`.
  Repeated names (case-insensitive) become `Name (2)`, `Name (3)`. Two `label.new` with the SAME text are ONE
  signal (true if either runs); every other call site is its own signal.
- Markers are static: `shape.*` -> up/down arrow, circle or square; `location.*` -> above / below bar;
  `location.absolute` makes the series a price (fires where it is not na, marker at that price); `label.new` is
  drawn at `y` (`yloc.abovebar/belowbar` honoured), label style decides up/down. Colours: TradingView constants
  (v6 red/teal/yellow values in v6), `#hex`, `color.new` / `color.rgb` of literals; anything dynamic -> default.
  Names reading as buy/long/bull/up get a green up-arrow below the bar, sell/short/bear/down a red down-arrow
  above, unless the script says otherwise.
- Hidden styling is honoured: `display=display.none`, `show_last=0`, a fully transparent colour (`color.new(c, 100)`,
  `color.rgb(r, g, b, 100)`, `#RRGGBB00`) or v4 `transp=100` give a signal WITHOUT a marker: the `sig` block works,
  the chart draws nothing for it.
- Merged `label.new` calls (same text): the FIRST call's marker style (shape, colour, location) is used for all of
  them. This is intentional: one signal has one marker style; give the calls different texts to style them apart.
- `alertcondition` is not drawn by TradingView; we draw a small circle above the bar (yellow `#f5c542`, or the
  buy/sell default) so it is visible.
- v4 `plotshape` / `plotchar` are re-bound by v4 position and `transp` dropped; in v5/v6 `transp` is an error.
  v6 needs a bool series (`location.absolute` excepted); v4/v5 accept numbers (non-zero = true).
- Errors with line:col: other `label.*` uses, a label stored in a variable, `x` other than `bar_index`/`time`,
  non-literal text, `offset` != 0 ("offset not supported"), `plotarrow`, `line.*` / `box.*` / `table.*`.
- Titles never reach generated JS; only slot numbers do (`rt.signal(i, cond)`, `rt.signalAt(i, price, always)`).

## Blocks
- `IndicatorBlockDef.signals?: { key, label, marker? }[]`; instances return 1/0 under the signal keys next to
  numeric outputs (keys unique across both), and may implement `markerPrice(key)`.
- `sig_<id>`: Boolean block with dropdown field `SIGOUT` (not `SIGNAL`: MACD has a `signal` parameter), same
  SOURCE input and params, plus `signalOnly` params (RSI overbought 70 / oversold 30, which the numeric RSI block
  does not show). Hoisted and stepped every bar like `ind_` blocks. An `ind_` and a `sig_` block of the same
  settings each get their own instance (duplicate work, identical values) — kept simple on purpose.
- Keys are slugs of the (deduplicated) titles, handed out in source order across plots and signals: anything
  appended later (a plot, a same-titled signal) never changes an existing key. Inserting a same-titled call EARLIER
  in the file does renumber the later ones (there is no other stable identity for a call site).
- A block whose chosen output / signal no longer exists never reads another one: the editor's fixup records the
  vanished choice (key + last known title) in the block's Blockly `data` string (Blockly itself would fall back to
  the first option), and the compiler reports "signal "Up" no longer exists in the script" on that block until the
  user picks a value (which clears it) or the script gets that output back (which restores it). A missing or
  unknown `SIGOUT` in saved JSON is also an error, never a default.
- A Pine script with only signals has no `ind_` block; saved blocks of a kind that no longer exists load as
  placeholders and fail compilation with a message saying which block to use.
- Built-in signals: Supertrend (new; same rules as the Pine template, flips = signals), MACD line/signal crosses,
  RSI leaving oversold / overbought, the SOURCE value (close by default) crossing the Bollinger bands ("Close above
  upper band" / "Close below lower band": breakout events drawn as neutral blue triangles, not buy/sell), Stochastic
  %K/%D crosses. Supertrend's flip test reads the close, exactly like the Pine template.

## Chart
- Signals used by the strategy are drawn with its auto-overlays (one overlay per indicator + settings, numeric and
  signal uses merged). The Pine tab's "Show on chart" draws a saved script with default inputs and all signals.
- Price-pane markers are merged with trade markers on the candles; sub-pane markers sit on the indicator's first
  line (a signal-only sub-pane script marks the candles). Signal markers are smaller and their text starts with
  "◇". At most the last 1000 markers per signal are drawn, with text only when a signal has <= 150 markers.
  A legend lists each signal (shape, colour, count) and, under the crosshair, the signals of that bar.
